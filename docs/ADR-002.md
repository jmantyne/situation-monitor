# ADR-002: API Selection — Free, Key-Free, Real-Time Environmental Data

**Date:** 2026-05-27
**Status:** Accepted
**Product version:** v2.1.1

---

## 🇬🇧 English

### Context

The requirement was to monitor real environmental conditions across multiple continents simultaneously — air quality in California (seasonal wildfires), particulate matter in Dubai (desert dust even without a full sandstorm), and baseline weather conditions in Finland, Kenya, and Australia. A single dashboard needed to surface all of this at a glance.

The key question was how difficult it would be to integrate open APIs, and whether anything needed to be installed or configured on Claude's side to make them work.

### Options Considered

API selection was made collaboratively based on requirements. The primary filter was: **free, no API key required, reliable, and with sufficient data resolution** for the use case.

The map layer required the most iteration — colour schemes and tile styling do not yet fully match the author's vision, but the current CartoDB Voyager implementation is a solid foundation for future improvement.

The composite MAP PIN score (avg of UV · AQI · Wind) turned out to be a particularly effective design decision: it creates meaningful variation across cities and gives the map real informational value at a glance.

### Decision

The primary driver was **economic**: the chosen solution works reliably and costs nothing to operate. It is also future-proof — if the dashboard is ever ported to a native iOS application, all selected APIs remain valid without modification.

The 5-minute refresh interval was a deliberate safety choice: wildfire smoke is acutely toxic, and the author wanted near-real-time situational awareness when monitoring conditions in fire-prone areas.

| Data | API | Key required | Cost |
|------|-----|-------------|------|
| Weather, UV, wind, pressure | api.open-meteo.com | No | Free |
| AQI, PM2.5, NO₂ | air-quality-api.open-meteo.com | No | Free |
| Sunrise / sunset | api.sunrise-sunset.org | No | Free |
| Home city detection | ip-api.com | No | Free |
| Map tiles | CartoDB Voyager via Leaflet | No | Free |

### Consequences

**Positive:**
- API integration was dramatically simpler than expected. No authentication flow, no token management, no SDK installation — plain `fetch()` calls returning clean JSON.
- All five APIs have performed reliably across all 11 cities with no failures observed during development.
- The MAP PIN composite score (UV · AQI · Wind average) produces meaningful geographic variation and adds real value to the map view.
- Zero ongoing cost enables indefinite operation without budget approval.

**Negative / Trade-offs:**
- Free-tier APIs carry implicit rate limits; the 5-minute refresh was partly chosen to stay well within those limits.
- Map styling flexibility is constrained by the tile provider — the current colour palette is functional but not yet optimal.
- Paid API integrations (tested separately in a private project) require credit card setup and secure API key storage — additional complexity not present here.

### Lessons Learned

As a former telecoms engineer (5 years), the author had never encountered API integration this straightforward. The contrast with traditional carrier-grade interfaces — complex authentication, SDKs, documentation hundreds of pages long — is striking.

The broader lesson: **the what and the where matter more than the how**. Once the requirement was clear (compare air quality and UV across 5 countries in real time, free, no server), the implementation was straightforward. Clarity of intent is the hardest part of any technical project — the engineering follows.

## 🇫🇮 Suomi (alkuperäinen)

### Context

Halusin tutkia, kuinka helppoa on integroida avoimia API-rajapintoja ja pitääkö Clauden puolelle asentaa jotain niiden saamiseksi toimimaan. Kaliforniassa on joka vuosi maastopaloja ja ilmansaasteet sekä hiukkaset ovat kiusa — samoin Dubain hiekkapöly, vaikka varsinaista hiekkamyrskyä ei olisikaan. Nyt pystyn vertaamaan tilannetta USA:ssa, UAE:ssa ja Suomessa sekä näkemään, millainen tilanne on ystävilläni Sydneyssä ja Nairobissa — kaikki yhdellä kertaa.

### Options Considered

Teimme valinnat Clauden kanssa yhdessä vaatimusteni perusteella. Kartan kanssa oli melkoista säätämistä — nykyiset värit eivät ole vielä optimaaliset, mutta karttojen rakenne ei anna periksi ajatukselleni. MAP PIN avg (UV · AQI · WIND) on hieno kombo ja kartalla on paljon vaihtelua sen ansiosta.

### Decision

Pääasiallinen motivaatio oli puhtaasti taloudellinen: ratkaisu toimii varmasti ja sen käyttö ei maksa mitään. Samalla jos teen tästä joskus iOS-applikaation, valittu ratkaisu on future-proof ja skaalautuva. Viiden minuutin päivitysväli liittyy siihen, että metsäpalojen savukaasut ovat tappavan myrkyllisiä — haluan nähdä tilanteen päivittyvän mahdollisimman usein.

### Consequences

API-integraatio ei voisi olla tätä helpompaa. Toisessa, täysin erilaisessa yksityisessä projektissani päädyin ostamaan Clauden API-rajapinnan käyttöä — siinäkin isoin urakka oli luottokorttinumeron syöttäminen ja API-avaimen kopioiminen turvalliseen paikkaan.

### Lessons Learned

Vanhana telecom-insinöörinä (5 vuotta töitä alalla) en ole koskaan nähnyt näin helppoa ja intuitiivistä API-integrointia. Tärkeintä on tietää mitä halutaan ja minne halutaan mennä — sen jälkeen kaikki on vain implementointia ja validointia.
