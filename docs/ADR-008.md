# ADR-008: Continue the native Watch product in a separate repository

Date: 2026-09-22 UTC

Status: Accepted direction; repository migration completed

## Context

Situation Monitor began as a single HTML dashboard and evolved through the governed deliveries recorded in ADR-001–007. The owner then requested native Apple Watch use: quick Crown navigation, haptics, compact outdoor views, a map, saved places, local clocks, offline forecasts, battery information and optional activity rings.

The Watch work was developed and tested in AI-Development-Platform's prototype workspace. It has now moved to its own private product repository. This is a continuation of the product idea and requirements, not a claim that the browser app became a native binary or that all browser behavior is shared.

## Decision

1. Keep this repository as the MIT-licensed web/browser product, currently v3.2.3. It remains usable in Mac and phone browsers; no native macOS target is implied.
2. Continue native Watch implementation in [situation-monitor-watchOS](https://github.com/jmantyne/situation-monitor-watchOS). The imported baseline is 4.0.0 build 34. The initial source import and verification are identified by commit `755d5b9700f32b4192d52cd399ad9b5c9fb2fb49`.
3. Keep AI-Development-Platform responsible for the reusable orchestration, review methods and evidence policies. Product implementation and future Watch changes belong in the Watch repository.
4. Preserve the historical ADRs and their MIT notices in the native repository. Private visibility does not revoke rights to previously published MIT material. Source-code licensing, API data rights and App Store terms are separate matters.
5. Use English for code, UI and active documentation. README and ADR documents may have Finnish in their final section only.

## Native architecture and differences

The native implementation uses Swift/SwiftUI, WatchKit, MapKit, Core Location and optional local HealthKit activity summaries. Weather and air quality use two Open-Meteo source requests; solar events travel within the weather response. The native app does not use the browser product's ipapi lookup or Sunrise-Sunset endpoint.

The data layer separates bounded heavy presentation caches from lightweight map summaries, prioritizes the selected place, limits concurrent source requests and retains downloaded data for offline use. Clocks run from local system time and IANA zones. Five-minute foreground freshness is not a guaranteed five-minute background schedule: watchOS controls execution. Action view remains an app view, not an Apple watch face or a host for arbitrary complications.

The detailed native decision is [Watch ADR-008](https://github.com/jmantyne/situation-monitor-watchOS/blob/755d5b9700f32b4192d52cd399ad9b5c9fb2fb49/docs/ADR-008.md). ADR numbering is repository-local: this document records the product split; Watch ADR-008 records native architecture.

## Evidence and limits

The owner accepted build 34's physical navigation tests 1–3. The separate build 33 one-hour, 500-place simulator diagnostic completed 6,308 selections without functional failures; p95 63.46 ms and sustained median memory change −0.7344 MiB. The migration built successfully from the new checkout and all ten native regression suites passed. These results do not certify physical capacity, battery use, every screen size or accessibility.

The test target remains 100 places with at least 500-place testing. Physical sustained memory/battery, complete 5× load coverage, weak-network/long-offline and accessibility gates remain open. Commercial data rights, paid tiers, secure feedback delivery, an iPhone target and App Store publication are separate future decisions. No native release is created by this documentation change.

## Alternatives and consequences

Keeping everything in the HTML repository would mix different runtimes, release identities and licensing scopes. Keeping production source only inside the platform would mix a product with its development tooling. A separate native product repository gives each a clear history and owner-controlled delivery path.

A future iPhone target may share native domain/data code in the Watch repository, but that is not implemented yet. Bug reports and changes must name the affected product and build; browser acceptance is not transferred to Watch or vice versa.

## Suomeksi

Situation Monitorin selainversiosta syntyi uusi natiivi Apple Watch -kehityspolku. Kellotyö tehtiin ensin AI Development Platformin prototyyppinä ja siirrettiin omaan yksityiseen situation-monitor-watchOS-repositorioon. Lähtöversio on 4.0.0 build 34.

Tämä alkuperäinen repositorio säilyy MIT-lisensoituna selainprojektina, versiossa 3.2.3. Watch-repositorio omistaa kellosovelluksen jatkokehityksen; AI Development Platform kehitysmenetelmän, orkestroinnin ja näyttökäytännöt. Vanhojen MIT-aineistojen oikeudet säilyvät.

Kellosovelluksessa on paikalliset kellot, rajatut haut, offline-välimuisti, kartta, kruunu ja haptiikka. Se ei ole Applen kellotaulu. Hyväksytyt yksittäiset laitetestit ja simulaattorin 500 paikan koe eivät vielä tarkoita koko tuotteen akku-, suorituskyky- tai saavutettavuushyväksyntää. iPhone, kaupallistaminen ja App Store -julkaisu ovat erillisiä jatkopäätöksiä.
