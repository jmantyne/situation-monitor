# ADR-007: Sequential Conductor + ATR Improvement — Situation Monitor v3.2.3

**Date:** 2026-09-16 (UTC)
**Status:** Accepted direction; documentary record prepared for Human review
**Product delivery:** Situation Monitor v3.2.3, Human-accepted runtime `bcd24818ac79c63c1610789f04fa1594dd3ad558`
**Publication:** Not established by this record

---

## 🇬🇧 English

### Context

Situation Monitor ADR-005 and ADR-006 recorded Human-coordinated multi-model delivery and repeatability. AI-Development-Platform ADR-001 proposed reducing manual handoffs while preserving Human authority. The v3.2.3 API repair became the first external-product pilot of its sequential Conductor + ATR improvement loop.

The broken CARTO basemap returned an HTTP-success image carrying an API-key watermark. The Human requested an audit of all external dependencies, an effective repair and an actual correction loop. Market research and native/watch development are separate later packages.

### Options Considered

| Option | Benefit | Limitation |
|---|---|---|
| Single-model focused map patch | Small and direct; the separately reported Claude solution also selected OSM | That narrative does not establish the wider failure/recovery coverage |
| Parallel independent assessments of one baseline | Diverse initial evidence | Does not establish review of subsequent corrections |
| Sequential reviews of exact corrected candidates | Later reviewers can challenge earlier implementation and drive tested changes | Additional time, orchestration, provider access and evidence costs |

### Decision

Record and adopt the bounded sequential loop for this delivery, with named roles and immutable review identities:

```
Conductor scopes and freezes the task
  → Codex diagnosis
  → Conductor-directed Codex implementation
  → Claude review → Codex corrections
  → Grok challenge of the corrected candidate → Codex corrections
  → Claude final recheck
  → Human usability acceptance
  → separately governed GitHub delivery
```

Conductor coordinates inputs, execution, findings and evidence. Implementation between reviews was performed by the interactive Codex executor; this is not an unattended general-purpose writer. Provider stages consume separate frozen Git snapshots. A completed model response is advisory evidence, not permission to merge or release. GitHub remains the versioned source of truth after delivery; provider results cannot authorize writes themselves.

### Observed Outcome

| Contribution | Change supported by evidence |
|---|---|
| Codex diagnosis | Missing environmental data no longer appears healthy; failed/partial refreshes are disclosed; dependency failure handling and tests added |
| Claude review | Wrong fallback index selected Istanbul instead of Helsinki; replaced with a named city identity |
| Grok challenge | Stale overlapping responses, unbounded IP lookup and persistent map-error notice corrected |
| Claude recheck | Confirmed all three Grok corrections; three informational closure entries, no actionable findings |
| Human | Reported the preview works well and approved it |

The reviewed runtime passed 29/29 structural checks and 40/40 Chromium tests (24 existing, 16 added). One bounded live HTTP viewport showed the repaired OSM map; mocked failure tests and supplied live observations remain distinct from independent model source inspection. The OSM layer is HTTP/HTTPS-only with attribution and Referer; direct file opening discloses the basemap limitation.

### Consequences

The pilot demonstrates a traceable contribution from later reviewers to the delivered candidate. It does not prove general superiority over one model: the Human's separate Claude account used a different reported version/scope, and no equal-budget controlled comparison was performed. Neither speed nor cost advantage is established.

Home-detection provenance remains deferred. No physical-watch implementation, Safari/device certification, autonomous market-research capability or production validation of the platform is claimed. Preparation/validator failures and failed provider attempts remain retained rather than being rewritten as successes. The seven-stage successful-chain limit and per-stage timeout are bounded pilot controls, not proof of unattended sleep-safe supervision.

The product remains v3.2.3 because its runtime changes repair compatibility and error handling. The new process is a documented delivery milestone; documentation versions and platform implementation history are tracked separately. No minor or major product feature is implied merely by changing the development method.

### Lessons Learned

1. Review the corrected artifact, not an obsolete baseline.
2. Require a finding, correction and regression test to establish improvement; agreement alone is insufficient.
3. Distinguish completed execution, technical review, Human acceptance and publication.
4. Preserve security and trust through scoped snapshots, explicit external-provider permissions and authenticated Git delivery. SSH was verified with the existing key and macOS Keychain; no key was replaced.
5. Evaluate future loop performance against a same-baseline, same-budget single-model self-review control, including hidden failure cases, remaining defects, time and cost.

## 🇫🇮 Suomi

### Konteksti

Situation Monitorin ADR-005 ja ADR-006 kuvasivat ihmisen koordinoimaa monimallitoimitusta ja sen toistettavuutta. AI-Development-Platformin ADR-001 esitti käsin tehtävien siirtojen vähentämisen ihmisen päätösvalta säilyttäen. Version v3.2.3 API-korjauksesta tuli peräkkäisen Conductor + ATR -parannuskierroksen ensimmäinen ulkopuoliseen tuotteeseen kohdistunut pilotti.

CARTO palautti HTTP-onnistumisesta huolimatta kuvan, jossa oli API-avaimen vaatimisesta kertova vesileima. Ihminen pyysi kaikkien ulkoisten riippuvuuksien tarkistusta, toimivaa korjausta ja todellista korjauskierrosta. Markkinatutkimus sekä natiivi- ja kellosovellus ovat erillisiä myöhempiä työpaketteja.

### Harkitut vaihtoehdot

| Vaihtoehto | Hyöty | Rajoitus |
|---|---|---|
| Yhden mallin karttakorjaus | Pieni ja suora; erikseen raportoitu Claude-ratkaisu valitsi myös OSM:n | Raportti ei osoita laajempaa virhe- ja palautumistilanteiden kattavuutta |
| Saman lähtöversion rinnakkaiset arviot | Riippumattomia alkuhavaintoja | Ei osoita myöhempien korjausten katselmointia |
| Korjattujen versioiden peräkkäinen katselmointi | Myöhemmät arvioijat voivat haastaa aiemman toteutuksen ja saada aikaan testattuja korjauksia | Lisää aikaa, orkestrointia, palveluyhteyksiä ja evidenssityötä |

### Päätös

Kirjataan ja käytetään tässä toimituksessa rajattua peräkkäistä kierrosta:

```
Conductor rajaa ja jäädyttää tehtävän
  → Codexin diagnoosi
  → Conductorin ohjaama Codex-toteutus
  → Clauden katselmointi → Codexin korjaukset
  → Grokin haaste korjatulle versiolle → Codexin korjaukset
  → Clauden lopputarkistus
  → ihmisen käytettävyyskatselmointi ja hyväksyntä
  → erikseen hallittu GitHub-toimitus
```

Conductor koordinoi aineistot, suorituksen, löydökset ja evidenssin. Katselmointien väliset toteutukset teki interaktiivinen Codex; kyseessä ei ole itsenäinen yleiskäyttöinen toteutusagentti. Arvioijat lukevat erillisiä jäädytettyjä Git-versioita. Mallin valmis vastaus on neuvoa-antavaa evidenssiä, ei yhdistämis- tai julkaisulupa. GitHub on toimituksen jälkeen versioitu yhteinen totuuslähde; palveluntarjoajan tulos ei itsessään valtuuta kirjoituksia.

### Havaittu tulos

| Osallistuja | Evidenssillä osoitettu vaikutus |
|---|---|
| Codex | Puuttuva data ei enää näytä terveeltä; epäonnistunut/osittainen päivitys ilmaistaan; riippuvuusvirheiden käsittely ja testit lisättiin |
| Claude | Helsinki-varavalinta osoitti indeksivirheen vuoksi Istanbuliin; korjattiin nimettyyn kaupunkiin |
| Grok | Korjattiin vanhan vastauksen ylikirjoitus, aikarajaton IP-haku ja pysyvä kartan virheilmoitus |
| Clauden lopputarkistus | Vahvisti kaikki kolme Grok-korjausta; kolme informatiivista sulkemismerkintää, ei korjattavia löydöksiä |
| Ihminen | Ilmoitti esikatselun toimivan hyvin ja hyväksyi sen |

Katselmoitu sovellus läpäisi 29/29 rakennetarkistusta ja 40/40 Chromium-testiä (24 vanhaa, 16 uutta). Yksi rajattu HTTP-selainnäkymä osoitti korjatun OSM-kartan toimivan. Simuloidut virhetestit ja Conductorin live-havainnot erotetaan mallien omasta lähdekoodin lukemisesta. OSM toimii HTTP/HTTPS-yhteydellä lähdemerkinnän ja Referer-otsakkeen kanssa; tiedostona avaamisen karttarajoite kerrotaan käyttäjälle.

### Seuraukset

Pilotti osoittaa myöhempien arvioijien jäljitettävän vaikutuksen lopputulokseen. Se ei todista yleistä paremmuutta yhteen malliin nähden: erillisen Claude-raportin versio ja laajuus erosivat, eikä samaan lähtöversioon ja budjettiin sidottua koetta tehty. Nopeus- tai kustannusetua ei osoitettu.

Kotipaikan tunnistusmenetelmän näyttäminen jäi myöhemmäksi. Kellototeutusta, Safari- tai laitesertifiointia, itsenäistä markkinatutkimusta tai alustan tuotantovalidointia ei väitetä tehdyksi. Valmistelun ja paikallisen validaattorin virheet sekä epäonnistuneet palveluntarjoajayritykset säilytetään. Seitsemän onnistuneen vaiheen raja ja vaihekohtainen aikaraja eivät osoita valvomatonta lepotilaturvallista suoritusta.

Tuoteversio säilyy v3.2.3:na, sillä toiminnalliset muutokset korjaavat yhteensopivuutta ja virheenkäsittelyä. Uusi menetelmä on dokumentoitu toimituksen virstanpylväs; dokumenttiversiot ja alustan toteutushistoria kirjataan erikseen. Pelkkä kehitysmenetelmän muutos ei tarkoita uutta minor- tai major-tuoteominaisuutta.

### Opit

1. Katselmoi korjattu tuotos, älä vanhentunutta lähtöversiota.
2. Osoita parannus löydöksellä, korjauksella ja regressiotestillä; yksimielisyys ei riitä.
3. Erota valmis suoritus, tekninen katselmointi, ihmisen hyväksyntä ja julkaisu.
4. Säilytä tietoturva ja luottamus rajatuilla tilannekuvilla, ulkoisten palvelujen täsmällisillä luvilla ja tunnistetulla Git-toimituksella. SSH varmennettiin nykyisellä avaimella ja macOS:n avainnipulla; avainta ei vaihdettu.
5. Vertaa jatkossa saman lähtöversion ja budjetin yhden mallin itsearviointiin, mittareina myös piilotetut virhetapaukset, jäljelle jäävät virheet, aika ja kustannukset.
