# ADR-001: Single-File HTML Dashboard on an iOS / Cloud-Native Dev Stack

**Date:** 2026-05-27
**Status:** Accepted
**Product version:** v2.1.1
**Superseded by:** — *(supersede with a new ADR if ported to React, Vue, or native iOS)*

---

## 🇬🇧 English

### Context

The goal was to learn how to use Claude AI entirely from an iPhone, working from the couch. The chosen infrastructure was a Dropbox/Claude cloud setup for all materials, with version control and distribution handled through a brand-new GitHub account — including the GitHub iOS app installed on the phone.

A single HTML file was chosen because the author had previously built similar tools from the command line, and the format is inherently future-proof: no build step, no dependencies, no server required.

### Options Considered

**Development environment:**

| Option | Reason rejected |
|--------|----------------|
| MacBook Pro (12 years old) | Could no longer install the Claude desktop app |
| New Mac Mini | Upfront hardware investment; Claude advised against it at this stage |
| **iPhone + Safari + GitHub CodeSpace** | ✅ Selected — zero hardware cost, operational same day |

**Application architecture:**

| Option | Reason rejected |
|--------|----------------|
| React / Next.js | Requires Node.js, a build step, and a hosting platform; adds weeks of setup before writing a single line of product code |
| Multi-file HTML + JS | Same hosting simplicity but adds file management overhead with no benefit at this scale |
| CodePen / JSFiddle | Not deployable as a real product; no version control integration |
| Replit | Server-side dependency; requires an account and persistent runtime |
| **Single HTML file + GitHub Pages** | ✅ Selected — no build step, no server, no dependencies; deployed in minutes |

### Decision

**A single HTML file deployed via GitHub Pages**, developed entirely through a browser-based interface (Claude web app + GitHub CodeSpace), with no local development machine.

This was chosen over framework-based alternatives because:
- It can be opened by anyone with a browser — no install, no server, no build step
- It deploys in minutes to GitHub Pages with zero configuration
- It is future-proof: the same file works as a web app, a downloaded file, or as the starting point for a native iOS app
- It keeps the entire development workflow within tools accessible from an iPhone

The trade-offs accepted consciously:
- `unsafe-inline` required in CSP (inline script is inseparable from single-file design)
- File size hard limit of 200 KB before a build step becomes necessary
- Grid layout is fixed to 12 cells (11 cities + 1 map) — adding cities requires layout rework

### Consequences

**Positive:**
- The full development environment was operational within a single day.
- Claude's guidance steadily increased appetite for more: the project evolved toward automation, pre-commit hooks, regression tests, and semantic versioning.
- Watching Claude and Stanford AI videos together accelerated understanding of the broader AI landscape.
- Collaboration quality improved continuously across iterations.

**Negative / Trade-offs:**
- Paid API integrations had to be dropped (one was successfully implemented, but the security architecture approach made it unsustainable).
- GitHub was the largest source of friction: repository migrations, manual fixes, and learning SRI hash verification the hard way. These were, however, the most valuable learning moments of the project.
- The single-file architecture scales to approximately 200 KB before a build step becomes necessary.

### Lessons Learned

iOS-based "couch coding" works surprisingly well for prototype and portfolio-level work. As of 2026-05-27 it does not yet replace a 100-person technical team — but that boundary will begin to shift within a few quarters.

The most significant personal insight: having operated professionally as a Technical Program Manager, Product Manager, architect, and Business Development Manager, the author observes that these roles are converging. In the near future, the human brings vision, narrative, and quality control; Claude delivers the implementation.

## 🇫🇮 Suomi (alkuperäinen)

### Context

Halusin lähteä oppimaan Claude AI:n käyttöä niin, että kaikki tapahtuisi iOS-applikaation avulla sohvalta käsin. Samalla päätin käyttää Dropbox/Claude-setupia pilvessä kaikelle materiaalille, ja versionhallinta sekä jakelu tehtäisiin minulle aivan uudella GitHub-tilillä, jonka iOS-applikaation asensin myös puhelimeen.

Päädyin yhteen HTML-tiedostoon, koska ennen olin tehnyt niitä itse komentoriviltä — ja ajattelin sen olevan myös future-proof eli skaalautuva lähtökohta ilman ylimääräisiä riippuvuuksia.

### Options Considered

Harkitsin 12 vuotta vanhan MacBook Proni käyttöä sekä mahdollisesti uutta Mac Miniä. MacBookiin ei enää voinut asentaa Claude-applikaatiota, ja Claude suositteli ettei vielä investoida Mac Miniin. Päädyimme siksi Safarissa ajettavaan Claude-webappiin sekä GitHubiin, jonka kautta avautui myös CodeSpace — selainpohjainen koodausterminaali.

### Decision

**Yksi HTML-tiedosto GitHub Pages -jakelussa**, kehitettynä kokonaan selainpohjaisessa ympäristössä (Claude-webappi + GitHub CodeSpace) ilman paikallista kehityskonetta.

Tämä valittiin framework-pohjaisten vaihtoehtojen sijaan koska:
- Kuka tahansa voi avata sen selaimella — ei asennusta, ei serveriä, ei build-steppiä
- Deployaus GitHub Pagesiin onnistuu minuuteissa ilman konfigurointia
- Se on future-proof: sama tiedosto toimii web-appina, ladattuna tiedostona tai iOS-natiivisovelluksen lähtökohtana
- Koko kehitystyönkulku pysyy iPhonelta saavutettavissa olevissa työkaluissa

Tietoisesti hyväksytyt trade-offit:
- `unsafe-inline` pakollinen CSP:ssä (inline-skripti on erottamaton osa single-file-designia)
- Tiedoston kokoraja on 200 KB — sen jälkeen tarvitaan build-step
- Grid-layout on kiinteä 12 soluun (11 kaupunkia + 1 kartta) — kaupunkien lisääminen vaatii layout-uudelleensuunnittelun

### Consequences

**Positiiviset:**
- Koko kehitysympäristö oli pystyssä saman päivän aikana.
- Clauden tuki ja ohjaus nosti ruokahalua: etenimme kohti automaatiota ja automaattisia tarkistuksia (pre-commit hook, regressiotestit, semver).
- Katsoimme yhdessä Clauden ja Stanfordin AI-videoita — ymmärrykseni kasvoi huomattavasti.
- Yhteistyö parani koko ajan iteraation myötä.

**Negatiiviset / Trade-offfit:**
- Jouduimme jättämään maksulliset API-integraatiot pois (saimme yhden toimimaan, mutta lähestymistapamme turvallisuusarkkitehtuuriin teki siitä kestämättömän).
- GitHub tuotti eniten haasteita: siirsimme repositoryä, teimme manuaalisia korjauksia, opimme SRI-hash-verifioinnin kantapään kautta. Nämä olivat kuitenkin projektin arvokkaimpia oppimiskohteita.
- Yhden tiedoston arkkitehtuuri skaalautuu noin 200 KB:iin — sen jälkeen tarvitaan build-step.

### Lessons Learned

iOS-pohjainen "sohvakoodaus" toimii todella hyvin prototyyppitasolla ja portfoliokäytössä. Se ei vielä 27.5.2026 korvaa 100-hengen teknistä tiimiä, mutta muutaman kvartaalin päästä tämä alkaa muuttua.

Suurin henkilökohtainen oivallus: olen toiminut ammattilaisena Technical Program Managerin, Product Managerin, arkkitehdin ja Business Development Managerin rooleissa. Tulevaisuudessa nämä roolit yhdistyvät saumattomasti — ihminen tuo vision, narratiivin ja laadunvalvonnan; Claude toteuttaa implementoinnin.
